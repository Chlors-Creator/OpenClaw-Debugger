## OpenClaw Debugger 跨平台重构（方案三）

**分支**：`refactor/split-core-shell`（已提交 `ccc9781`，未推送；`main` 未动）

### 背景
项目原为单工程 WPF 应用（`net10.0-windows`，根目录 77 个 .cs）。目标是为 macOS 版本铺路。
此前讨论过三个方案（零搬迁旁挂 mac 目录 / 只验证 / 完整拆分），用户选择**完整拆分**。

### 已完成的目录结构
- `src/OpenClawDebugger.Core`（`net10.0`）：Abstractions / Bridge(19) / Connection(5) / Remote(17) /
  Features{Stickers,Memory,Models,Plugins,Skills,Artifacts,Backup} / Storage(3) / Aliyun(5) / Assets(3 py)
- `src/OpenClawDebugger.Platform.Windows`（`net10.0-windows` + UseWPF）：凭据管理器、DPAPI、
  ssh 路径探测、WPF 缩略图编码、explorer 打开目录
- `src/OpenClawDebugger.Platform.Mac`（`net10.0`，零第三方依赖）：Keychain（security CLI）、
  AES-GCM 快照加密、sips 缩略图、/usr/bin/open
- `src/OpenClawDebugger.Shell.Windows`：App/MainWindow/AssemblyInfo/WebView2BridgeTransport
- `shared/WebUi`：界面唯一真源，两个壳用 `Content Include + Link` 复制
- `tools/OpenClawDebugger.ContractGen`：替代 `Tools/Generate-BridgeContract.ps1`（已删除）
- `tests/OpenClawDebugger.Tests`：改为 `net10.0`，macOS 可运行
- `build/build-win.ps1`、`build/build-mac.sh`

### 关键决策
- 全部工程 `RootNamespace = OpenClawDebugger`，因此 71 个搬家文件的 `using` 与命名空间**零改动**。
- 六个抽象接口：`IBridgeTransport`、`ICredentialStore`、`ISecretProtector`、
  `ISshExecutableLocator`、`IThumbnailEncoder`、`IShellLauncher`。
- `SshExecutableLocator.Current` 是静态注入点，避免改动 `SshCommandRunner.ResolveExecutable()`
  的全部调用点；Windows 壳在 MainWindow 构造函数里注册 `WindowsSshLocator`。
- 快照文件后缀保留 `.dpapi`，避免 Windows 上历史回滚快照失效。
- 嵌入资源用 `<LogicalName>OpenClawDebugger.*.py</LogicalName>` 保留原有硬编码资源名。
- `.NET 10 SDK` 的 `dotnet new sln` 默认生成 `.slnx`，已手写经典 `.sln` 以兼容旧版 VS。

### 环境注意
- 本机 macOS 原本没有 dotnet，已装到 `~/.dotnet`（10.0.404，未写入 PATH，需 `export PATH="$HOME/.dotnet:$PATH"`）。
- mac 上可交叉编译 WPF：靠 `EnableWindowsTargeting=true`（已在 `Directory.Build.props` 按 OS 条件设置）。
- 已验证：整个解决方案 0 错误 0 警告，13 项测试全部通过，`shared/WebUi` 正确复制到输出目录。

## 2026-11-11 追加：macOS 壳最小可运行版本（提交 `f74f5d1`）

### 技术路线确认
- 本机**未安装 Xcode**（仅 CommandLineTools）→ 排除 `net10.0-macos` 原生 AppKit 路线。
- 选用 Avalonia 12.1.6 + `Avalonia.Controls.WebView` 12.1.1（AvaloniaUI 官方包，

  把 `window.chrome.webview` 映射到 `invokeCSharpAction`；WebView2 环境检测到原生存则直接空转。
  前端 5 处 `chrome.webview` 调用零改动。

### 新增文件

  绕开 WKWebView 对 `file://` 的 fetch/CORS 限制；带路径穿越防护与 no-store。
- 冒烟开关：`OPENCLAW_SMOKE=1` 时探针结束 6 秒后自动退出。

## 2026-11-11 追加：Xcode 与壳路线的最终结论

- **Xcode 实际已安装**：`/Applications/Xcode.app`，Xcode 27.2（27B52），许可已接受，
  macOS SDK 27.2。`xcode-select -p` 指向 `/Library/Developer/CommandLineTools`，
  所以 `xcodebuild` 默认报错——**这不是"没装 Xcode"**。用
  `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` 即可调用，不需要 sudo。
- **结论：仍保持 Avalonia 壳，不改原生 AppKit。** 依据：两者都跑 WKWebView，
  差异只在壳的形态（包体、原生菜单、App Store 沙箱）；而本项目的风险在桥接装配、
  Keychain/SSH 验证、文件选择通道，不在壳。换壳会把时间花在不产生功能的地方。
  触发再评估的条件：要上 Mac App Store / 需要菜单栏常驻与自动更新 / 包体敏感 /
  Avalonia WebView 在拖拽或输入法上出问题。迁移成本低（`IBridgeTransport` 已抽象）。
- 待确认：`Avalonia.Controls.WebView` 文档挂在 Accelerate（商业线）下，
  nuspec 声明 MIT，正式分发前需核实授权条款。

### SDK 事故与复原（重要，避免重复踩坑）
- 尝试 `dotnet workload install macos` 时：① 沙箱拒绝删除 `~/.dotnet` 下旧清单；
  ② 我用 `rm -rf` 清清单，误删了 `sdk-manifests/10.0.100/microsoft.net.workload.emscripten.current/10.0.115`，
  导致 SDK 报 `MSB4242 工作负载集 10.0.404 缺少清单`，**整个构建失效**。
- 复原方法（已验证有效，无需重装 SDK）：
  1. 装一份干净 SDK 到临时目录作为参照（`~/.dotnet2`）；
  2. 用干净副本覆盖回 emscripten 的 `WorkloadManifest.json` / `.targets`；
  3. 把损坏的 `sdk-manifests/10.0.400` 与 `metadata/workloads` **移出** `sdk-manifests`
     （不能改名留在目录内，目录名会被当作 feature band 解析而报 FormatException）；
  4. 验证：全解决方案构建通过、13 项测试通过、清单与干净安装逐字节一致。
- 现状：`~/.dotnet` 已恢复正常（10.0.404），临时副本已删除；备份留在
  `~/.dotnet-workload-backup/`（可删）。`macos` workload **仍未安装**，
  原生路线需要用户自行执行一次 `dotnet workload install macos`。
- 教训：不要用 `rm -rf` 动 SDK 的 `sdk-manifests`；workload 安装失败优先用
  `dotnet workload repair`，或另装独立 SDK 目录，不要手工删清单。

## 2026-11-11 追加：桥接装配完成（提交 `44681f0`）

### 实现
- `AvaloniaBridgeTransport : IBridgeTransport`：响应经
  `InvokeScript("window.__openclawHostDeliver(<json>)")` 投回页面；JSON 直接作为
  对象字面量嵌入，仅转义 U+2028/2029；跨线程投递统一 `Dispatcher.UIThread.Post`。
- `MainWindow` 成为完整组合根，与 Windows 壳逐项对应：`MacKeychainCredentialStore`、
  `MacSecretProtector`、`SipsThumbnailEncoder`、`UnixSshLocator`、`FinderShellLauncher`。
- `BridgeDispatcher` 增加可选构造参数 `allowedOrigins`（默认 `https://openclaw.local`），
  来源比较改为 scheme+host+port 全等；mac 侧传入 `http://127.0.0.1:<port>/`。
- `NativeWebView` 的消息事件**只暴露 `Body`，没有来源 URI**（反射确认），
  因此由壳声明自己的来源，并配合 `NavigationCompleted` 里的 `location.href` 校验兜回越界导航；
  `NewWindowRequested` 一律 `Handled = true`。
- 诊断开关：`OPENCLAW_BRIDGE_LOG=1` 打双向消息，`OPENCLAW_SMOKE=1` 探针后自动退出。
