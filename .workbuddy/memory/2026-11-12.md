### turn-buffer 改为 5 秒静默自动放行（21:40-21:55）
- 改 `~/src/qqbot-turn-buffer/src/middleware/turn-buffer.ts`：新增 `SILENCE_WINDOW_MS = 5000`、
  `armSilenceFlush()`；`PendingTurn` 增加 `silenceTimer` / `flush` / `released` / `lastDiagnostic`。
  结束标记 `（）`/`~`/`～`/`QAQ` 保留为「立即放行」的快捷方式（实测 0ms 放行且标记被剥掉）。
- **关键实现约束**：静默路径不能调 `ctx.stop()`。`stop()` 把 `ctx.stopped` 永久置真，而
  `runMiddlewareChain` 的 `dispatch()` 开头就是 `if (ctx.stopped) return`，之后再调用捕获的 `next()`
  会被直接短路，下游（typingIndicator / envelopeFormatter / `bot.emit('message')`）一个都不执行。
  正确做法是**只 return 不 stop**，把 `next` 存进定时器延后调用——此时 chain 的 index 仍停在
  turn-buffer 层，`dispatch(index+1)` 不会触发 "next() called multiple times"。
- 竞争处理：每条新消息都会重绑 `pending.flush` 到自己的 ctx 并重置 5s 定时器；`released` 标志保证
  TTL 与静默窗口不会重复放行。
- 冒烟测试（把 turn-buffer 单独 tsup 打包 + 手写 fake ctx，`HOME=/tmp/tbhome` 隔离存储）四场景全过：
  单条 5s 放行、三条（间隔 700ms）合并成 `"我在\n路上堵车\n晚点回"`、`~` 立即放行、标记后 5s 不重复。
  `ctx.stop()` 调用次数 0。
